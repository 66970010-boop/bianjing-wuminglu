# 铜钱运动连续性修复

## 已确认原因与修改

- 三维 render() 原来每帧调用 centerGroup()，翻转轮廓变化会引起整组横向补偿；现在仅在布局尺寸变化时校准。
- 原来的随机三角布局可能使三枚铜钱交换区域，移动路径相交；现在固定左、中、右通道，随机仅在附近微调，外侧间距保持对称。
- 原来起抛直接设置新水平朝向，临落地叠加高频正弦晃动，结束后 settle() 又重置旋转圈数；现在从实际位置、角度连续插值，旋转目标沿正方向累计，不再末帧重置，不再叠加晃动。
- 三维总投掷时长仍为2100ms，未降低播放速度。保持原模型、贴图、缩放、相机和页面布局。
- 图片备用模式原来立刻更换钱面，并四次压扁/撑开；现在温和透视变化，在腾空中段交接正反面，末帧保持目标钱面。
- 两种动画均为单一循环，重复触发返回正在执行的动画，销毁时取消回调。

assets/fortune/coin-stage.js、coin-fallback.js 为源文件；build-classic.cjs 重新生成 fortune-classic.js，直接打开 HTML 的入口也同步更新。

- HTTP服务模式：重新构建的普通脚本，三维八种组合实际运行，模型可见面检查全部通过；固定区域避免轨迹跨区。最大落定水平中心偏差小于0.005像素。
- 三维采样1240帧，最长帧间隔30.1ms。帧率数据不能单独证明运动自然。
- 六轮完整成爻流程保存次数为1、2、3、4、5、6，结果入口出现，无控制台错误。
- 独立运行备用模式，确认启用canvas2d并完成八轮；该模式的面值检查来自传入结果，不视为独立图像识别证明。
